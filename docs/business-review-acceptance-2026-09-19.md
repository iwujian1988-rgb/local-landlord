## 范围与判断标准

重点检查入住、出账、部分收款、退租退款、欠费展示、提醒、照片保存和后台合同管理。以可复现业务场景及修复前失败/修复后通过的测试作为依据，不以健康检查替代业务验收。本次不做基础设施重构，不自动部署生产。

## 已修复问题

| 业务场景 | 原问题 | 修复结果 |
| --- | --- | --- |
| 入住时明确填写实收 0 元 | 可能被默认收款逻辑当作已收 | 保留 0 元语义，账单未结清 |
| 分次收款 | 一分钱尾款可能消失，超额或三位小数金额可能进入流水 | 按分核算，校验本次收款金额 |
| 后台确认部分收款账单 | 再记录整笔收入，重复计算现金收入 | 只记录剩余应收，同步累计实收和收款日期 |
| 已退租作废账单 | 后台仍可能确认收款或催缴 | 拒绝收款，跳过催缴 |
| 编辑账单项目 | 非法金额或已收款账单修改可能破坏账实一致性 | 保存前校验，保护已有收款 |
| 修改付租周期 | 初始已计费覆盖范围被改变 | 保留初始周期，后续规则单独更新 |
| 水电抄表 | 电费更新可能覆盖固定水费；历史部分收款状态未保护 | 保留固定费用，按实际已收金额保护账单 |
| 提前退租退款 | 房间入口与租客入口处理不一致；按现价估算可能多退 | 共用退租流程与历史账单退款计算，写退款流水 |
| 多期或部分预付退款 | 只看最后一笔全额账单，忽略其他实收或已消耗租金 | 汇总可退款账单，扣除已消耗租金，不把纯水电账单当租金 |
| 上月欠费、本月已付或本月不收租 | 首页或房间状态可能漏掉旧欠款 | 保留历史未结欠费，统一房间列表和详情状态 |
| 已预付多月 | 非收款月份仍提示临近收租 | 根据计费周期和真实未结账单判断 |
| 已出账后更改收租日/费用规则 | 展示和提醒可能改用新规则，已出账单失真 | 优先使用账单保存的金额与到期日 |
| 关闭费用规则 | 停用项仍可能触发待收提醒 | 停用项不参与未出账周期计算 |
| 收租提醒 | 部分收款金额、跨月到期或停用房东处理不一致 | 使用剩余应收与账单到期日，排除停用房东 |
| 删除房间/房产 | 抄表记录可能残留或阻碍外键删除 | 在事务中清理相关抄表记录 |
| 后台上传合同 | 按收据类型保存，合同列表与小程序不一致 | 使用合同类型保存和查询 |
| 新建房间照片 | 上传成功但表单未接收照片，保存后丢图 | 接入照片暂存交接，上传未完成不可继续，保存可访问 URL |
| 小程序/H5 账单展示 | 重算明细掩盖历史尾款；H5 展示全额或已结清仍展示付款码 | 使用账单总额和剩余应收，完整展示多月账期 |
| 登录失效或上传/保存失败 | 多请求重复登录、异常响应仍可能继续成功流程 | 合并重新登录，校验业务响应，后台失效清理登录态 |
